# Сохранение состояния юнита

Документ описывает модель хранения состояния, жизненный цикл томов и
поведение активностей после перехода на git и данные внутри юнита.

## Целевая модель

- `/app` юнита — external-том `unitman_unit_app_<UnitId>`.
- Данные внутреннего Docker — external-том `unitman_unit_docker_<UnitId>`.
- Данные podman-варианта — external-том `unitman_unit_containers_<UnitId>`.
- `projects/<ProjectId>/mainBranch/.git` монтируется в юнит read-only как
  `/seed/git` и используется только для первичного seed.
- Вложения готовятся на хосте в `<unit>/seed/volumes` и монтируются в юнит
  read-only как `/seed`.

Тома создаются runner-ом перед `docker compose up` и не удаляются командами
`docker compose down` или `docker compose down -v`.

## Операции

### Сборка

`NachatSborkuUnitaActivity`:

1. делает `git fetch` нужной ветки в `mainBranch`;
2. читает `unitman.yaml` через `git show origin/<Branch>:unitman.yaml`;
3. возвращает конфиг, не копируя проект и не трогая `/app` юнита.

Рабочее дерево и `.git` юнита не изменяются.

### Подготовка

`NachatPodgotovkuUnitaActivity`:

1. копирует служебные файлы и генерирует `compose.yaml`, `Dockerfile`, `.env`;
2. создаёт external-тома, если их ещё нет;
3. запускает контейнер и ждёт готовности dockerd и `/app`;
4. если в томе нет `.git`, делает `git init` и `fetch` ветки из `/seed/git`;
5. если `.git` уже есть, делает `fetch` и `pull --rebase --autostash`;
6. засеивает вложения, у которых ещё нет маркера;
7. восстанавливает кэши и выполняет пользовательские команды;
8. читает `unitman.yaml` из рабочего дерева юнита.

### Обновление

`NachatObnovlenieUnitaActivity`:

1. проверяет наличие `compose.yaml` и `.env`;
2. создаёт external-тома при необходимости;
3. поднимает контейнер, если он остановлен;
4. выполняет `git fetch` и `pull --rebase --autostash` внутри `/app`;
5. не выполняет push.

Ветка берётся из `.env` (`UNITMAN_BRANCH_NAME`). Если переменной нет,
используется текущая ветка репозитория. `origin` берётся из `/app/.git/config`;
`set-url` выполняют только Build и Prepare, где есть `StorageUrl`.

### Сброс подготовки

`NachatSbrosPodgotovkiUnitaActivity` выполняет пользовательские команды
остановки и `docker compose down` без `-v`. Контейнеры удаляются, тома
состояния остаются.

### Удаление

`NachatUdalenieUnitaActivity`:

1. выполняет `docker compose down -v`;
2. явно удаляет external-тома по `UnitId`;
3. best-effort удаляет тома старой схемы, если в `.env` есть
   `COMPOSE_PROJECT_NAME`;
4. удаляет каталог юнита, включая старый host-каталог `app`.

## Git-политика

- Seed и обновление не выполняют `checkout -f`, `reset --hard` или `clean`.
- Грязное рабочее дерево сохраняется через `pull --rebase --autostash`.
- При смене ветки локальные изменения уходят в stash; при конфликте stash
  сохраняется, активность возвращает ошибку.
- Push разрешён как явное действие изнутри юнита. Активности никогда не пушут
  автоматически.
- `StorageUrl` редактируется при логировании шагов, чтобы токен не попадал в
  прогресс.

## Вложения

- Вложения лежат в `/app/unitman_volumes/<Dir>`.
- Маркер seed: `/app/.unitman/volumes/<Dir>`.
- Если маркера нет, runner скачивает архив в `<unit>/seed/volumes/<Dir>`,
  после чего скрипт копирует файлы в целевой каталог без перезаписи
  существующих файлов.
- Если маркер есть, том не скачивается и не изменяется.
- Обновить вложение можно только удалением юнита и повторной сборкой.

## Что сохраняется

Сохраняется между пересборками и пересозданием контейнера:

- рабочее дерево `/app`, включая изменённые и неотслеживаемые файлы;
- `.git` и локальные коммиты;
- вложения в `unitman_volumes`;
- данные внутреннего Docker/podman;
- локальные контейнеры и их тома внутри внутреннего движка.

Не сохраняется при пересоздании контейнера:

- пакеты, установленные в ОС юнита вне `/app` (`apk add`, `dnf install`);
- изменения в `/etc`, `/root` и других каталогах вне именованных томов;
- глобальные кэши пакетных менеджеров вне `/app`.

Эти изменения требуют отдельного тома или пересборки базового образа.

## Rollout без миграции

Старые host-каталоги `unit/app` и старые compose-тома не мигрируются.
После первого успешного seed новый host-каталог `app` удаляется, а старые
Docker-тома остаются на диске.

Перед очисткой старых томов убедитесь, что все юниты остановлены. Пример
поиска томов старой схемы:

```sh
docker volume ls --format '{{.Name}}' | grep -E '_(unit_docker_data|unit_app|unit_containers)$'
```

Удаление выполняется только после проверки списка:

```sh
docker volume rm <volume-name>
```

## Ограничения

- Состояние сохраняется только в пределах одного `UnitId`. Переименование
  юнита не поддерживается и приведёт к новым томам.
- Если удалить external-том вручную, следующий Prepare создаст пустой том и
  засеет его заново из git и вложений.
- Если в юните остались локальные коммиты, `pull --rebase` может потребовать
  разрешения конфликтов. Конфликт не удаляет данные: изменения остаются в
  рабочем дереве или stash.
- Токен в `StorageUrl` хранится в `/app/.git/config`; при ротации токена
  обновление через Update может требовать повторной подготовки.
